Diseño del tablero de Power BI: producción de petróleo y gas, pozo por pozo

Cómo armarlo en Power BI Desktop

  1. Instale Power BI Desktop (gratuito, solo para Windows) y abra un informe en blanco.
  2. Cree un parámetro de texto llamado CarpetaSalidas con la ruta de la carpeta outputs\powerbi de este proyecto.
  3. Cree una consulta por tabla (15) con el código de la sección «Power Query». Cada consulta carga un archivo Parquet; deje el nombre de la consulta igual al de la tabla.
  4. En la vista de modelo, cree las 25 relaciones de la tabla «Relaciones»: cardinalidad uno a varios (1:*), dirección del filtro única (de la dimensión al hecho), todas activas. No cree relaciones bidireccionales ni inactivas.
  5. Marque dim_calendar como tabla de fechas con la columna month_start.
  6. Ordene month_name_es por month, year_month_label por period_key, horizon_label por horizon y method_name_es por sort_order. Oculte las columnas de clave de los hechos.
  7. Cree una tabla vacía llamada _Medidas («Especificar datos» sin filas) y agregue en ella las medidas de la sección «Medidas DAX», con su formato.
  8. Cree las 5 páginas a escala 16:9 (1280 × 720 px) y ubique cada visual según la grilla de 12 columnas de la sección «Las cinco páginas».
  9. Guarde el informe como .pbix. Cuando corra el flujo, vuelva a cargar con «Actualizar»: las consultas leen los mismos archivos.
La conexión Parquet.Document es la que usa Power BI Desktop para leer archivos Parquet; si su versión no la ofrece, use «Obtener datos» con el conector Parquet y apunte a los mismos archivos.

El modelo en estrella

Ocho dimensiones alrededor y siete hechos al centro. La jerarquía Provincia, Concesión, Yacimiento, Pozo vive dentro de dim_well (estrella, no copo de nieve). La operadora está en los hechos porque cambia con el tiempo; dim_well[operator_current_name] es solo un atributo.

Medidas DAX

Todas van en la tabla _Medidas. Las de pronóstico se generan por fluido y cuantil con una plantilla; sumar el P10 o el P90 de varios pozos no da el del total, por eso los visuales agregados lo rotulan «Suma de P10 por pozo».

Petróleo producido (m³)

Petróleo producido en el período filtrado. Formato: #,0.

Petróleo producido (m³) =
SUM ( fact_production_monthly[oil_m3] )

Gas producido (miles de m³)

Gas producido en el período filtrado. Formato: #,0.

Gas producido (miles de m³) =

Agua producida (m³)

Agua producida en el período filtrado. Formato: #,0.

Pozos en producción

Pozos con petróleo o gas mayores que cero. Formato: #,0.

Filas por mes

Filas de producción por mes: sirve para ver un mes incompleto. Formato: #,0.

Filas por mes =
COUNTROWS ( fact_production_monthly )

Petróleo año anterior (m³)

Petróleo producido 12 meses antes de cada mes filtrado. Usa: [Petróleo producido (m³)]. Formato: #,0.

Petróleo año anterior (m³) =
VAR periodos = VALUES ( dim_calendar[period_index] )
RETURN CALCULATE ( [Petróleo producido (m³)], REMOVEFILTERS ( dim_calendar ),
        TREATAS ( SELECTCOLUMNS ( periodos, "p", dim_calendar[period_index] - 12 ), dim_calendar[period_index] ) )

Variación interanual petróleo (%)

Variación del petróleo producido frente al mismo mes del año anterior. Usa: [Petróleo año anterior (m³)], [Petróleo producido (m³)]. Formato: 0.0%.

Variación interanual petróleo (%) =
DIVIDE ( [Petróleo producido (m³)] - [Petróleo año anterior (m³)], [Petróleo año anterior (m³)] )

Petróleo P10 (m³)

Volumen P10 proyectado de petróleo del método en uso, para el origen elegido (el más reciente si no se elige). Sumar el P10 o el P90 de varios pozos no da el del total: es el de pozos que se mueven juntos y es más ancho que el verdadero. Formato: #,0.

Petróleo P10 (m³) =
VAR origen = IF ( ISFILTERED ( dim_origin[origin_period_key] ),
        SELECTEDVALUE ( dim_origin[origin_period_key] ),
        CALCULATE ( MAX ( dim_origin[origin_period_key] ), REMOVEFILTERS ( dim_origin ) ) )
RETURN CALCULATE ( SUM ( fact_forecast[p10] ), dim_fluid[fluid_key] = "oil",
        fact_forecast[is_selected] = TRUE (),
        dim_origin[origin_period_key] = origen )

WAPE (%)

Error absoluto ponderado: suma del error absoluto sobre la suma de lo real. Formato: 0.0%.

WAPE (%) =
DIVIDE ( SUM ( fact_backtest_metrics[sum_abs_error] ), SUM ( fact_backtest_metrics[sum_actual] ) )

MAE

Error absoluto medio, en la unidad del fluido. Formato: #,0.0.

MAE =
DIVIDE ( SUM ( fact_backtest_metrics[sum_abs_error] ), SUM ( fact_backtest_metrics[n] ) )

RMSE

Raíz del error cuadrático medio, en la unidad del fluido. Formato: #,0.0.

RMSE =
SQRT ( DIVIDE ( SUM ( fact_backtest_metrics[sum_sq_error] ), SUM ( fact_backtest_metrics[n] ) ) )

Sesgo (%)

Positivo: el método proyecta de más. Formato: 0.0%.

Sesgo (%) =
DIVIDE ( SUM ( fact_backtest_metrics[sum_error] ), SUM ( fact_backtest_metrics[sum_actual] ) )

Cobertura P10-P90 (%)

Proporción de pares con lo real entre P10 y P90; el objetivo es 80 %. Formato: 0.0%.

Cobertura P10-P90 (%) =
DIVIDE ( SUM ( fact_backtest_metrics[n_covered] ), SUM ( fact_backtest_metrics[n] ) )

Objetivo de cobertura

Cobertura que debería tener una banda P10-P90. Formato: 0.0%.

Objetivo de cobertura =

Pinball escalada

Pérdida pinball de los tres cuantiles sobre la suma de lo real; mide a la vez la mediana y las bandas. Formato: 0.000.

Pinball escalada =
DIVIDE ( SUM ( fact_backtest_metrics[sum_pinball] ), SUM ( fact_backtest_metrics[sum_actual] ) )

Antigüedad de los datos; más de 55 días es una publicación tardía. Usa: [Último mes publicado]. Formato: #,0.

VAR k = [Último mes publicado]
